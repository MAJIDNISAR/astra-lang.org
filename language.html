Variables, inference, and strings

Types are inferred from initializers; annotations are optional and checked when present. Template literals interpolate with ${}.

let name = "Astra";          // inferred str
let version: float = 0.9;   // explicit annotation
let tests = 449;            // inferred int

print("${name} v${version}, ${tests} tests green");

Recursion, control flow, loops

fn fib(n: int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

fn main() -> int:
    for i in 0..10:
        print("fib(${i}) = ${fib(i)}")
    return 0

while, do/while, switch, break/continue, and for-range loops all compile to native code today.

Structs, enums, and pattern matching

struct User:
    name: str
    age: int
    active: bool

let u = User { name: "Ada", age: 36, active: true }
print(u.name)  // typed field access, native GEP loads

enum Status:
    Active
    Suspended
    Deleted

let label = match status:
    Status::Active    => "ok"
    Status::Suspended => "paused"
    Status::Deleted   => "gone"

Result<T,E>, no exceptions

Fallible operations return Result. The compiler forces the caller to handle both arms; there is no invisible control flow.

fn divide(a: int, b: int) -> Result<int, str>:
    if b == 0:
        return Err("division by zero")
    return Ok(a / b)

match divide(10, 2):
    Ok(value)  => print("result: ${value}")
    Err(cause) => print("failed: ${cause}")

Closures

Closures capture from the enclosing scope. The compiler lifts them into standalone functions at compile time (lambda lifting), so a closure call is exactly as fast as a plain function call.

fn main() -> int:
    let factor = 3
    let scale = |x: int| { x * factor }  // captures factor
    print(scale(5))  // 15, native call
    return 0

Generics and gradual typing

Generic functions are monomorphized, specialized per concrete type at compile time, like Rust and C++, so generics carry zero runtime cost.

fn max<T>(a: T, b: T) -> T:
    if a > b:
        return a
    return b

When a boundary genuinely can't be typed statically, data from an LLM, a dynamic config, dyn marks it explicitly. Checks defer to runtime at that boundary and nowhere else.

fn handle(payload: dyn) -> dyn:
    // statically compatible with every type;
    // the escape hatch is visible in the signature
    return payload

Nominal traits

A trait declares method signatures; an impl … for … block implements them for a concrete type. An impl that misses a method, or whose method signature differs from the trait, is the compile error E0020, which names it.

trait Shape:
    fn area(self) -> int

impl Shape for Circle:
    fn area(self) -> int:
        return self.r * self.r

Dispatch is static: impl Shape for Circle lowers to Circle__area, exactly like an inherent method. A trait bound (fn total<T: Shape>(s: T)) calls the trait's methods and accepts only types that implement it (E0020 at the call site); @derive and standard traits are next.

Modules v0.10

Since v0.10, a program can span several files. import util; loads util.astra from the same folder (or from ASTRA_PATH, or a Mifa path dependency). Only items marked pub can be used from outside, and they are always named with their module, so it is clear where each one comes from.

util.astra 
pub const LIMIT: int = 100
pub struct Point:
    x: int
    y: int
fn helper(n: int) -> int:  // private to util
    return n * n
pub fn square(n: int) -> int:
    return helper(n)
main.astra 
import util

fn main() -> int:
    let p = util::Point { x: 3, y: 4 }
    print(util::square(p.x) + util::LIMIT)  // 109
    return 0

Import cycles, missing modules and private or unknown items are compile errors with code E0013, pointing at the import line, the same JSON diagnostics an agent already handles. Modules are resolved into one program before type checking, so the interpreter and the native compiler behave identically.

The compiler pipeline

Astra is implemented in Rust (~15 core modules) as a classic multi-phase compiler:

source.astra
  → lexer        tokens with line + column
  → parser       recursive-descent AST
  → modules      resolve imports into one program
  → closure lift closures → top-level functions
  → typechecker  type inference + checking
  → monomorphize generic specialization
  → IR           LLVM IR generation
  → llc + link   object code + small C runtime
  → native executable

Since v0.10, astra run takes a second path after type checking: a tree-walking interpreter that starts instantly and needs no LLVM. Every feature is tested for identical output and exit code on both engines, and a fuzzer generates programs to keep them in agreement.

Diagnostics are emitted as structured JSON at every phase, which is what makes the agent repair loop possible. The direction is locked in five ratified architecture decisions: ARC memory management, gradual typing via dyn, a single LLVM backend targeting native / WASM / GPU, AI primitives as keywords, and Python interop via embedded CPython.
