Astra against C, Rust, Go, Java, Node.js and Python

Test: seven workloads, each written the normal way in every language, with the input size N passed on the command line (as the Computer Language Benchmarks Game does), so no compiler can precompute a result. benchmarks/run.py times each program as one process run (one warm-up, then the median of 7 runs; 2 for Python and the Astra interpreter) and fails if any output differs. Spread between runs was typically a few percent; the machine was not idle (load average 4–12 of 12 cores). Apple clang 17 -O2 · rustc 1.94 -O · Go 1.26 · OpenJDK 25 · Node 25 · Python 3.11 · Astra via LLVM -O2. Median milliseconds, lower is better.

"Rust -O, checked" is Rust with overflow-checks=on. Astra checks every integer operation for overflow and stops with a runtime error, so this is the like-for-like comparison. Java and Node.js include their VM start-up (about 40 ms) in every run.

What the numbers say

  • Floating point: in mandelbrot (from the Benchmarks Game) Astra is faster than C and Rust: 56 ms against 60–68 ms.
  • Plain computation: Astra is at parity with overflow-checked Rust on fib, loop and collatz (144 / 113 / 177 ms against 155 / 107 / 168). Against unchecked Rust and C it is 1.3–2.5× slower, the price of always-on overflow checking (unchecked compilers can also vectorize the plain loop), not of the code generator.
  • Structs and arrays: structs match checked Rust; arrays are within about 20%. A struct that doesn't outlive its scope now lives on the stack, and array reads and bounds checks are compiled inline (each workload was 5–18× slower than Rust before).
  • Strings: faster than C and Rust in this workload (123 ms against 214–231): "item-" + i.to_string() formats the number straight into the result, with no temporary string and no printf. Go is faster still (86 ms).
  • Against Python: native Astra is 5–200× faster.
  • The interpreter (astra run, no LLVM needed) now beats CPython on the plain loop (7.5 s vs 22.6), mandelbrot and arrays, sits within noise on collatz, and trails only on recursive calls (fib), structs and strings. A redesign landed this round: each function body is lowered once to slot-resolved form, no name lookups, no AST-walk dispatch, then extended to structs, arrays, tuples, templates, for-each and match.

Scope honesty: seven small programs on one laptop that wasn't isolated, not a language shoot-out. Of the Benchmarks Game's standard programs only mandelbrot is included so far: the others (fannkuch-redux, n-body, spectral-norm, binary-trees) need features Astra doesn't have yet, assigning to array elements and recursive structs, and will be added as those land.

Native speed, including compile time

Claim: for compute-shaped work, Astra's compile-then-run beats Python's run alone.

Test: scenario 3 runs the same 2,000,000-iteration arithmetic loop in both languages; each command is timed as one process run.

astra
72 ms
python3
158 ms

Result: ~2.2× faster, compile included, 68 ms to compile (parse, type-check, LLVM IR, llc, link) plus 4 ms to run, against 158 ms for Python to run the loop. Run alone, the binary is about 40× faster.

Scope honesty: one small loop, chosen to show the architecture (native code with little compile overhead), not a general speed-up figure. The first compile after the machine has been idle is cold (about 300 ms while the LLVM tools load from disk), and macOS scans each newly built binary on its first launch (about 180 ms). The seven-language comparison below is the broader picture.

Verify after every edit

Claim: verify is cheap enough that an agent can call it after every edit, like a linter, with compiler guarantees.

Test: time astra verify (full parse + typecheck, no codegen) on a representative program.

Result: 4–5 ms wall-clock. At that latency verification costs far less than a single LLM round-trip, there is no reason for an agent not to verify after every edit.

The repair loop closes

Claim: an agent can take broken source, get a structured diagnosis, repair it, and reach a native binary, fully mechanically.

Test: scenario 1 feeds a program with an undefined variable to astra verify --error-format=json, asserts the JSON carries the exact line/column/error_code, applies the fix, and asserts the binary compiles and prints the expected output.

Result: pass, broken → JSON(line 2, col 13, E0002) → repaired → native, in one scripted pass.

Agent mistakes rejected before execution

Claim: the classes of error LLMs most commonly generate never reach runtime.

Test: scenario 2 submits four canonical mistake programs; each must be rejected by verify with the right error class, and none may produce a binary.

Mistake classExampleCaught pre-run
Undefined variableprint(totl) (typo)yes, E0002
Type mismatchlet n: int = "hello"yes, E0004
Wrong argument countadd(1) for add(a, b)yes, E0005
Invalid return typereturning str from -> intyes, E0004

Result: 4/4 rejected, in Python, all four would execute until the faulty line is reached (or silently succeed).

Deterministic dependency resolution

Claim: the same manifest always resolves to the same lockfile, byte for byte.

Test: resolve a workspace, hash astra.lock, wipe, resolve again, compare sha256.

Result: sha256-identical across repeated runs. A build an agent verified once stays verified, no drifting transitive dependencies.

Real programs, checked against Python

Eight everyday programs give exactly the same answers as a Python reference, on both engines.

Each program solves a task developers actually have: summarising a server log, a CSV sales report, validating a config file, restocking inventory, grading, a password policy, text search and a Mandelbrot plot. Each has an independent Python reference, and Astra's output must match it byte for byte on the interpreter and natively. Writing them found three native wrong answers, fixed in v0.12.2 and logged with the tests that guard them. Since v0.13.2 none of the eight needs a workaround: they count with Map and rank with sort_by_key as a developer would. Measured on v0.13.3-alpha, 2026-11-06.

Run it yourself

Once public downloads open (coming soon), the compiled-binary side reproduces in a minute: write the loop and time it —

$ astra verify loop.astra               # type-check: a few ms
$ time astra compile loop.astra --output loop && ./loop
$ time python3 loop.py                  # the comparison

The full harnesses (scripts/validate_metrics.sh, benchmarks/run.py with the seven-language programs, and the test suite) ship with the compiler source, which opens at v1.0-beta. If a number on this page doesn't reproduce on your machine, that's a bug, tell us.
